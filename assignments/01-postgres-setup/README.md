# Задание 1 Подключение к PostgreSQL (Ромашов С.П)

## Задание

1.	Установить Postgresql 18 на docker.
2.	Создать базу данных c настройками Lang = ru_RU.UTF-8, аутентификация  scram-sha-256 (по умолчанию).
3.	Создать в пользователя с доступом USAGE к этой БД и схеме public в ней.
4.	Разработать приложение на любимом языке программирования, удовлетворяющее следующим требованиям:
4.1.	Подключаться к БД и выполнять sql запрос:
SELECT VERSION();

Разработанное приложение должно:

1.	Считывать настройки подключения к БД лежать рядом в файле, например *.conf или *.json, *.yaml, *.toml.
2.	Получать от пользователя логин и пароль для подключения к БД, консоль / графически интерфейс.
3.	Каким либо образом безопасно соединять данные из файла и полученные от пользователя, там образом, чтобы пользователь своим вводом не мог добавить своих опций в параметры подключений к БД.


## Структура

- `compose.yaml` запускает PostgreSQL и публикует порт только на localhost;
- `docker/Dockerfile` добавляет русскую локаль в официальный образ PostgreSQL;
- `docker/postgresql.conf` содержит настройки сервера;
- `docker/init-user.sh` создаёт ограниченного пользователя;
- `app/config.toml` содержит несекретные параметры подключения;
- `app/main.py` запрашивает логин и пароль и выводит версию сервера;
- `run.sh` подготавливает Python, запускает PostgreSQL и приложение.

## Быстрый запуск

Из каталога задания выполните:

```bash
./run.sh
```

При первом запуске скрипт создаст локальные `.env` и `.venv`, установит
зависимости, соберёт контейнер, дождётся готовности PostgreSQL и запустит
приложение. Если `.env` уже существует, скрипт сохранит его без изменений.

После завершения приложения PostgreSQL продолжит работать. Остановить его можно
командой `docker compose down`.


## Запуск PostgreSQL

Создайте локальный файл с секретами:

```bash
cp .env.example .env
```

Замените демонстрационные пароли в `.env`, затем соберите и запустите сервер:

```bash
docker compose up --build --detach
docker compose ps
```

При первом запуске контейнер создаст базу `rsp` и пользователя из переменной
`APP_DB_USER`. Для базы выдаётся право `CONNECT`, для схемы `public` — `USAGE`.

## Запуск приложения

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r app/requirements.txt
python app/main.py
```

Введите значения `APP_DB_USER` и `APP_DB_PASSWORD` из локального `.env`.
Программа должна вывести строку, начинающуюся с `PostgreSQL 18`.

## Безопасность параметров подключения

Файл `config.toml` содержит только разрешённые несекретные поля: `host`, `port`,
`dbname` и `connect_timeout`. Программа отклоняет неизвестные поля и проверяет
их типы и допустимые значения.

Логин и пароль передаются в `psycopg.connect()` отдельными именованными
аргументами. Они не объединяются с конфигурацией в строку подключения, поэтому
пользователь не может добавить через ввод параметры наподобие `host`, `port`
или `options`. Пароль вводится через `getpass()` и не отображается в терминале.

Файл `.env` с локальными паролями исключён из Git. В репозитории хранится только
`.env.example` с демонстрационными значениями. `.env` не связан с `.venv`:
первый содержит переменные запуска, второй — изолированное окружение Python.

## Проверка настроек

После запуска сервера можно проверить локаль и способ хранения пароля:

```bash
docker compose exec postgres psql -U postgres -d rsp -c \
  "SELECT datname, datcollate, datctype FROM pg_database WHERE datname = 'rsp';"

docker compose exec postgres psql -U postgres -d rsp -c \
  "SHOW password_encryption;"
```

Остановить контейнер:

```bash
docker compose down
```

Удалить контейнер вместе с учебными данными и повторить полную инициализацию:

```bash
docker compose down --volumes
```

Удаление volume требуется также после изменения имени базы или параметров её
первичной инициализации: скрипты из `docker-entrypoint-initdb.d` выполняются
только при создании нового каталога данных.
